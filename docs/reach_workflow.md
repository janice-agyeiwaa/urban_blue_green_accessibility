# Reach Access Workflow

## Goal
Rebuild the physical/reach access workflow from spatial inputs using Python.

## Current base layer
- Layer: `allparks_land_buffer`
- Records: 114
- CRS: NAD 1983 UTM Zone 10N / EPSG:26910
- Reason for use: The project documentation defines access points as access to the waterfront land buffer, not the full park polygon.

## Step 1: Candidate access point generation
Access points were generated by intersecting the land buffer boundary with walkable OpenStreetMap network lines downloaded using OSMnx.

### Inputs
- `allparks_land_buffer`
- OpenStreetMap walking network from OSMnx

### Method
1. Read the 114 edited land buffer polygons.
2. Convert each polygon to WGS84 for OSMnx.
3. Download the walking network around each park buffer.
4. Convert OSM lines back to EPSG:26910.
5. Convert each land buffer polygon to its boundary.
6. Intersect OSM walking lines with the land buffer boundary.
7. Extract point geometries from the intersection results.
8. If no exact intersections were found, try a fallback using OSM lines within 3 m, then 5 m of the boundary.
9. Save raw candidate access points.

### Outputs
- `data/interim/reach/candidate_access_points_raw.gpkg`
- `data/interim/reach/candidate_access_points_failed_parks.csv`

## Notes / assumptions
- The edited land buffer is treated as the waterfront access zone.
- OSMnx is used instead of the original Composite Network to make the workflow reproducible from open data.
- Exact intersections are preferred.
- 3 m and 5 m fallback points are only used when a park has no exact intersection.
- Parks with no exact or fallback candidates are flagged for QA.

## Current issues
- 14 parks still have no OSM-based access candidates.
- OSM may not contain all local trails, informal paths, plazas, or park entrances.
- Cleaning is still needed to remove duplicates and weak candidate points.
